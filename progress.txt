## Codebase Patterns

- Winner attribution remains server-authoritative and bound to the current latest call, but mark order must not affect eligibility.
- Flexible-pattern attribution must inspect every canonical mask rather than relying only on the progress display's selected closest variation.
- Database command adapters map the persisted latest called ball to the actor's card-cell index and pass `null`, never `-1`, when that ball is absent from the card.
- Preserve the incomplete-to-complete transition check, serializable persistence, command idempotency, event sequencing, and persist-before-broadcast behavior.
- Continuation carry-forward must use the integrity-bound winning command's marked projection; current marks include later co-winner-window activity, while removing the triggering-call mark reintroduces mark-order dependence.
- A participant can have multiple integrity-bound winner contexts in one round after winning successive stages; continuation must tolerate that history and select the unique context matching the current winner row's trigger, confirmation time, card, and stage pattern.
- Frozen winner progress must remain a subset of authoritative calls and marks; later additions are allowed, but missing historical rows or an unmapped winning ball must fail closed.
- No database migration, wire-contract change, retroactive winner reconstruction, or browser-only winner decision is in scope.
- Winner presentation must follow authoritative co-winner and result stages, not completed client progress; an unrelated latest call may leave a fully marked pattern active without presenting a false winner.
